## 0. Read this first

Sonarar is **Flutter**, not Godot. Everything below is Flutter idiom: `Theme`-less per-widget
`TextStyle`s, a `Skin` value object, JSON theme files, and `LayoutSpec` constants.

| | |
|---|---|
| Repo | `F:\App Projects\Music Player\sonarar-player` — `pham-noah/sonarar-player`, `main` |
| App root | `app_src/` (`pubspec.yaml`, `lib/`, `test/`) |
| UI | `lib/screens/` (34 files), `lib/widgets/` (25), 58 529 lines of Dart under `lib/` |
| Token surface | `lib/theme/skin.dart` (`Skin`, `LayoutSpec`), `lib/theme/motion.dart`, `lib/theme/layout.dart`, `lib/theme/surface.dart`, `assets/themes/*.json` (12 files → 6 skins × 3 layouts) |
| Gates | touched test → `flutter test` → `flutter analyze`; native paths (`"C:/src/flutter/bin/flutter.bat"`, never the MSYS `/c/...` form) |

The app is not broken. It is **undecided**: it has three parallel design languages (the skewed
Sonar slab, the flat Solid plate, the floating Glass card), a token layer that exists but is
mostly bypassed, and a contrast system that works on the dark themes and fails on the light
ones. That is what this document fixes — decisions, not a repaint.

## 1. Audit

Findings are numbered `F-n`. Severity is `P0` (fix before the next build) or `P1` (next
convenience pass). Every measurement is from the live render or from the code at the audited
commit.

### 1.1 Colour and contrast

**F-1 (P0) The muted-text ladder fails on every light theme, and it fails silently.**
Muted text is painted as `textSecondary.withValues(alpha: a)` (`skin.dart:62`). Nine themes
need nine different alphas to reach the same 4.5:1, but the call sites use whatever number
felt right at the time — **28 distinct alphas** in `lib/`.

| theme | `secondary(0.55)` | lowest alpha that clears 4.5:1 |
|---|---|---|
| abyss | 5.45:1 ✓ | 0.49 |
| mono | 2.86:1 ✗ | 0.78 |
| minimal | **2.27:1 ✗** | **0.90** |
| bloom | **2.31:1 ✗** | **0.89** |
| solid/midnight | 3.55:1 ✗ | 0.65 |
| glass/aurora | 3.77:1 ✗ | 0.62 |

On Minimal the artist line under every track title is 2.27:1. No alpha below 0.85 can pass on
`minimal`/`bloom` at all — the ladder is structurally incapable of working there.

**F-2 (P0) The accent is used as text, and on light skins it is illegible.**

| theme | accent on bg | verdict |
|---|---|---|
| minimal `#E8927C` | **1.88:1** | fails at any size |
| bloom `#D98BA6` | **2.07:1** | fails at any size |
| crimson `#E60012` | 4.12:1 | large text only |
| abyss `#3CE0D0` | 12.19:1 | fine |

The active tab label, every section-mark label, every caps eyebrow and the card icons are
painted in raw `accent`. On Minimal **the active tab is the least legible label in the tab
bar** — the state you are in reads worse than the states you are not. Visible in
`docs/design/before/sonar-minimal-home.jpg` (the `NOW` eyebrow) and `.../sonar-minimal-settings.jpg`.

**F-3 (P0) The plate has no edge, because both of its delimiting channels are sub-threshold.**
`KitRow` (`widgets/kit.dart`) delimits a row with (a) a translucent fill and (b) a hairline at
`secondary(0.22)`. Measured:

| | panel fill vs page | hairline `secondary(0.22)` |
|---|---|---|
| abyss | **1.33:1** | 1.77:1 |
| mono | **1.12:1** | 1.42:1 |
| minimal | 1.27:1 | 1.36:1 |

Non-text UI boundaries need 3:1. Both channels are under 2:1, so rows read as text floating on
the page and the "slab — the one shape this app repeats" (the comment in `kit.dart` says
exactly that) never appears. Only the 3px accent tick survives.

**F-4 (P1) Accent tints used as state are below the threshold too.** `accentAt(0.12…0.30)` — used
for panel borders, tab-bar top rules and toggle tracks — lands between 1.05:1 and 2.22:1 on
every theme. Fine as decoration, wrong as the only signal of state (see F-5, F-9).

### 1.2 Spacing and hierarchy

**F-5 (P0) The section header is the loudest thing on every screen, and it is not a control.**
`SectionBand` in `banner` form (`widgets/devices.dart:163`, chosen by
`assets/themes/*.json → chrome.sectionBand: "banner"` for the Sonar layout) is a full-bleed
accent slab with `onAccent` text and a hard offset shadow. On Settings there are two of them
plus a filled segmented control plus a filled CTA — four filled slabs of the same weight, and
the actual settings values are the quietest thing on the page.

The `mark` form (3px accent tick + 13px w800 label, `devices.dart:185`) already exists and is
used by the Solid and Glass layouts. **It is the better form and it is already written.**

**F-6 (P0) The settings row reserves a hard 104px for its value and clips the label to fit.**
`settings_screen.dart → _stepper`: `SizedBox(width: 104)` for the value, flanked by two 34×34
buttons. At 320dp the label gets the remainder and `maxLines: 1` + ellipsis (`kit.dart`) turns
it into `FADE…`, `SLEE…`, `WEA…` — while ~90dp of the row sits empty between the clipped label
and the stepper. See `docs/design/before/sonar-abyss-settings-small.jpg` and mockup sheet 2.

**F-7 (P0) Three unit formats for the same kind of value, in one column.**
`'${crossfadeSeconds}s'` (line 270) · `'${sleepTimerMinutes} min'` (284) ·
`'${weatherRefreshMinutes}m'` (296) → `5s`, `30 min`, `30m` stacked vertically.

**F-8 (P1) The committed screenshots are stale and contradict the app.** `docs/shots/*.png` are
from 27 Oct; the third tab has since changed from SEARCH (`Icons.search`) to SETTINGS
(`tab_bar_view.dart:83`), the settings screen has since gained a three-way
PLAYBACK/LIBRARY/SYSTEM strip, and `CROSSFADE` is now `FADE IN`. Anyone reading the docs gets
the wrong app.

**F-9 (P1) Dead space is the largest element on three screens.** Home, first-run and player
each end their content between 55% and 65% of the viewport height and leave 350–450px of empty
background above the mini player, with nothing anchoring the bottom. The layout is
top-weighted; a phone in one hand reads the top half and a void.

### 1.3 Typography

**F-10 (P0) There is no type scale — there are 14 sizes.** Sizes in use: `11 12 13 14 15 16 17
18 19 21 22 30 34 46`. Six of them sit between 13 and 19, i.e. inside the range where a
one-pixel difference is not a hierarchy, it is noise. `LayoutSpec` declares the intended ladder
(`fontFloor 16`, `fontRow 14`, `fontMicro 12`) and the code then steps around it with literals:
9× `fontSize: 13`, 4× `15`, 3× `17`, 3× `30`, 1× `21`, 1× `19`, 1× `11`
(`youtube_search_screen.dart:232`).

**F-11 (P0) Almost nothing is set at body weight.** Font weights in `lib/`: **88× w900, 66×
w800, 33× w700, 8× w600, 1× w500, 1× w400**. The app has no regular weight, so every row
label, value and caption competes at the same visual density and weight cannot express
hierarchy. Combined with F-10, a 14px label at w800 with +1px tracking reads as a headline.

**F-12 (P1) Tracking is not a scale either:** 10 distinct values (0.6, 0.8, 1, 1.2, 1.4, 1.5,
1.6, 2, 3, 4 px) passed to `trackingFor(context, px)` at 88 call sites.

### 1.4 Depth and shadow

**F-13 (P1) Shadows are invisible where they matter and wrong where they are visible.**
`Skin.slabShadow` is `0x8C000000` on dark themes — black at 55% drawn on `#04080F`, which is
itself near-black: measured difference ≈ 1.0:1, i.e. nothing. On light themes the same token is
`textPrimary @0.10`, a soft grey that reads as a smudge under the skewed bands rather than a
cast shadow. Meanwhile `glass_aurora.json` sets `"castShadow": true` with
`"shadow": "#00000000"` — a shadow token that is fully transparent on the theme whose whole
proposal is depth.

**F-14 (P1) The first-run CTA's hard shadow is a different hue from the button.** Visible as a
violet-blue wedge on the left edge of START LISTENING
(`docs/design/before/sonar-abyss-firstrun.jpg`); the offset layer takes `accentDeep` while the
button takes `accent`, which on Abyss is teal-cyan over blue.

### 1.5 Motion

**F-15 (P1) Two motion systems and 9 durations.** `lib/theme/motion.dart` declares press 55,
release 220, morph 180, artCrossFade 240, panel 220, tabArrival 260, tabBackdrop 430, stagger
300, staggerStep 42. Then `KitTabs` animates at `Duration(milliseconds: 140)` (a literal, not a
token), and every theme JSON overrides `tabTransitionMs` (260 or 420). Three sources of truth
for the same tab transition, and none of them is the token class.

**F-16 (P1) Arrival overshoots at hero size.** `MotionCurve.arrival = Curves.easeOutBack` with
`arrivalAmplitude: 1.0` on the Sonar themes moves a 46px headline backwards before it settles.
An overshoot reads as bounce at 12px and as a layout bug at 46px.

### 1.6 State feedback

**F-17 (P0) OFF is louder than ON.** `_toggle` passes only
`activeThumbColor: skin.accent` and `activeTrackColor: skin.accentAt(0.35)`; the inactive
track falls back to Material's outline. Measured on Abyss: OFF ring 21:1, ON track **2.32:1**
against the page and the knob **5.25:1** against its own track on dark — and **1.51:1** on
Minimal, where the knob disappears into the track entirely. The app shouts the state you are
not in.

**F-18 (P0) "Selected" means four different things, and sometimes changes the shape.**
Selected = filled accent + accent border in `KitTabs` (radius 4); filled skew slab in the
first-run LAYOUT row; **outline only** for the selected COLOURS chip (ABYSS is outlined where
PERSONA is filled — same screen, same widget family); a 2px underline in the tab bar; a
full-bleed slab for a section header. A control whose silhouette changes on selection cannot be
scanned.

**F-19 (P0) Dependent controls never render disabled.** `WEATHER VARIANTS`
(`settings_screen.dart:327`), `PLACES` (`:324`) and `WEATHER EVERY` (`:292`) are gated by
`prefs.allowNetwork` and `prefs.contextWeather`, but when the prerequisite is off the row still
draws at full contrast with a live toggle — the grep for a disabled state in
`settings_screen.dart` returns the stepper's own null-callback case and nothing else. The only
disabled styling that exists is `secondary(0.25)` at **1.9:1**, unlabelled.

**F-20 (P1) There is no error state for a failed read.** An unreadable music folder renders the
same empty state as "no music yet" — the repository exposes `accessDenied` and `missingIds`
(`library/library_repository.dart:21`) and the screen shows neither.

### 1.7 Responsiveness

**F-21 (P0) Four controls are under Android's 48dp minimum.**

| control | size | file |
|---|---|---|
| settings stepper −/+ | **34×34** | `settings_screen.dart → _stepButton` |
| `KitTabs` (PLAYBACK/LIBRARY/SYSTEM, LAYOUT…) | height **34** | `widgets/kit.dart` |
| `LayoutSpec.secondaryActionHeight` | **44** | `theme/skin.dart:258` |
| mini-player neighbour buttons | **44×48** (its own comment calls the 44 deliberate) | `screens/mini_player.dart:379` |

`LayoutSpec.tapTarget = 56` exists and is declared to be respected; none of these four use it.
The comment above the transport tokens records the same bug being fixed once for the transport
row only ("at 42×38 the shuffle and repeat keys were a 38px band under a thumb that covers 48").

**F-22 (P1) The screen gutter is asymmetric by design and by accident.**
`LayoutSpec.screenPadding = LTRB(30, 20, 20, 0)` — 30 left, 20 right, 0 bottom. Settings uses
`LTRB(20, 10, 20, 24)`, first-run `LTRB(20, 26, 20, 28)`, `KitRow` `LTRB(12, 7, 8, 7)`. Content
does not share a left edge across screens, and the bottom inset is inconsistent with the
mini-player + tab-bar height (`miniPlayerClearance = 70`).

**F-23 (P1) Content runs under the mini player.** On the settings and library screens the last
row is painted beneath the mini player and the gesture bar rather than scrolled clear
(`.../sonar-abyss-settings-small.jpg`, `.../light-minimal-settings.jpg`). The clearance token
exists; the scroll views do not add it.

## 2. Target look — the token set

Everything here is a **decision**, to be encoded once. Numerals are Flutter `double`s.

### 2.1 Colour

Keep every existing palette. Add three derived roles and one rule per role. Values are the
computed result of the rules, so the implementer can either implement the derivation or paste
the table — both give the same pixels.

| token | rule | used for |
|---|---|---|
| `textPrimary` | existing | titles, labels, values |
| `textSecondary` | existing | notes, subtitles |
| `textMuted` | `textSecondary` at the theme's 4.5:1 floor | artist lines, timestamps, inactive labels |
| `accentInk` | `accent` blended toward `textPrimary` to 4.5:1 | accent used as **text** or as a 1px glyph |
| `borderStrong` | `textSecondary` at the theme's 3.0:1 floor | the only border allowed to delimit a control |
| `borderSubtle` | `secondary(0.22)` — decoration only, never the only edge | dividers |

Computed values (all verified by `docs/design/tokens/derive_tokens.py`):

| theme | bg | textMuted | accentInk | borderStrong |
|---|---|---|---|---|
| abyss | `#04080F` | `#E2EEFA` @0.49 | `#3CE0D0` 12.19:1 | `#565D65` 3.01:1 |
| amber | `#000000` | `#FDFDFD` @0.46 | `#F3DF0C` 15.37:1 | `#5A5A5A` 3.04:1 |
| crimson | `#0A0A0C` | `#E8E8EE` @0.50 | `#EA2433` 4.52:1 | `#5D5D60` 3.01:1 |
| minimal | `#E9E4DC` | `#5C5955` @0.90 | `#875C51` 4.51:1 | `#86827D` 3.02:1 |
| mono | `#121213` | `#9A9AA2` @0.78 | `#D8D8DC` 13.17:1 | `#616166` 3.04:1 |
| bloom | `#F4E4DA` | `#665459` @0.89 | `#885B6A` 4.52:1 | `#928081` 3.01:1 |
| solid/midnight | `#0B1020` | `#A9B6D0` @0.65 | `#4C8DFF` 5.92:1 | `#576074` 3.00:1 |
| glass/aurora | `#0E1116` | `#B4BEC9` @0.62 | `#7FD1FF` 11.23:1 | `#5A6168` 3.01:1 |
| solid/forest | `#0A1410` | `#A9C6B7` @0.61 | `#4ADE80` 10.76:1 | `#52655C` 3.01:1 |

Rules:
1. `Skin.secondary(a)` **clamps** `a` to the theme's muted floor. One edit, and the 28 alphas
   in `lib/` stop being able to break contrast. The ladder collapses to three steps:
   **muted (clamped) · secondary (0.80) · primary (1.0)**.
2. Accent is either a **surface** (fill + `onAccent` content) or **ink** (`accentInk`) — never
   both in one control, never raw `accent` on text.
3. A control's boundary is `borderStrong`. `borderSubtle` is allowed only where a fill change of
   ≥3:1 already delimits the shape.

### 2.2 Type scale

Seven steps. Every value already exists in the app — this removes seven sizes, it does not add any.

| token | size / height / weight | used for |
|---|---|---|
| `display` | 34 / 1.05 / w900, tracking −0.4 | screen titles (SETTINGS, LIBRARY) |
| `hero` | 46 / 1.02 / w900 | home greeting |
| `title` | 22 / 1.15 / w900 | player track title, sheet titles |
| `body` | 18 / 1.35 / w400 | pitch text, empty-state body |
| `bodyBase` | 16 / 1.35 / w400 | notes, descriptions |
| `row` | 14 / 1.2 / w700, tracking +0.04em | settings row labels, list secondary |
| `micro` | 12 / 1.2 / w700, tracking +0.06em | caps eyebrows, badges, durations |

Weight ladder — **the change that does the most work**: `w900` display/hero/title only,
`w800` caps labels and values, `w700` row labels, `w400` body and notes. Body text at w900 is
why every screen reads as an all-caps poster.

Size migration (mechanical, no judgement needed):
`11→12 · 13→14 · 15→16 · 17→16 · 19→18 · 21→22 · 30→34`, and keep `12 14 16 18 22 34 46`.
Tracking values collapse to three: `0.16em` (section band), `0.08em` (button/caps label),
`0.02em` (body). `trackingFor(context, px)` stays the only path — it is script-aware and that
must not regress.

### 2.3 Spacing

4pt grid, eight steps: `s0 2 · s1 4 · s2 8 · s3 12 · s4 16 · s5 24 · s6 32 · s7 48`.

- Screen padding: **20 all round** (`s4`+`s1` is not a thing — set `EdgeInsets.all(20)`), plus
  bottom clearance `miniPlayerHeight + tabBarHeight + 24`.
- Row padding: `12 leading / 12 trailing`, vertical `8`.
- Vertical rhythm: `s2` between label and note, `s3` between rows, `s5` between groups, `s6`
  above a section header.
- Migration: every `SizedBox(height:/width:)` outside `{2,4,8,12,16,24,32,48}` snaps to the
  nearest step (20 values today; 13 widths).
- `LayoutSpec.gapS/gapM` (10/26) are retired in favour of `s3/s5`. They are currently used 7
  times in 58k lines — the token layer will only take hold if the literals go.

### 2.4 Corner radii

Three roles, one assignment table. The **skew and a radius never apply to the same control** —
that is the rule that stops the current mix of pills, skews and 4px boxes in one strip.

| token | value | applies to |
|---|---|---|
| `r-sm` | 4 | inline chips, badges, the accent tick |
| `r-md` | 12 | rows, cards, buttons, cover art |
| `r-lg` | 24 | sheets, floating panels |
| `pill` | 999 | the floating tab bar only |

`assets/themes/*.json → material.radii.{panel,card,bar,sheet}` keep overriding these per theme
(the Glass family needs 24/32), but the defaults move into `LayoutSpec` so a theme without
radii does not fall back to `surface.dart`'s hardcoded `4.0`.

### 2.5 Elevation

Four levels. The rule that makes them work on dark: **a shadow is not depth on a near-black
background — a rim light is.**

| token | dark | light |
|---|---|---|
| `e0` flat | none | none |
| `e1` plate | `borderStrong` 1px, no shadow | `borderStrong` 1px + `0 1px 2px rgba(29,26,22,.06)` |
| `e2` floating (mini player, CTA) | rim `inset 0 1px 0 rgba(255,255,255,.10)` + `0 6px 20px rgba(0,0,0,.45)` | `0 2px 6px rgba(29,26,22,.10)` |
| `e3` overlay (sheet, player panel) | rim + `0 12px 32px rgba(0,0,0,.55)` | `0 8px 24px rgba(29,26,22,.14)` |

`Skin.slabShadow` is retired. `material.castShadow` becomes `elevation: e0..e3` in the theme
JSON. The first-run CTA's offset layer takes `accentDeep` at `e2`, never a third hue (F-14).

### 2.6 Motion

Four durations, three curves, one stagger step.

| token | value | used for |
|---|---|---|
| `press` | 90ms `easeOutCubic` | a control going down |
| `release` | 160ms `easeOutCubic` | a control coming back up |
| `base` | 200ms `easeOutCubic` | morphs, panel open/close, tab container, art cross-fade |
| `screen` | 320ms `easeOutCubic` | tab change, backdrop settle, list arrival |
| `staggerStep` | 40ms, cap 5 items, total ≤ 320ms | list/row arrival |

- `easeOutBack` is permitted **only** for arrivals, with amplitude ≤ 0.5, and never on type
  larger than 22. `MotionCurve.arrival` becomes `easeOutCubic` at `screen`.
- Theme JSON `motion.tabTransitionMs` becomes an enum reference: `"base" | "screen"`. Arbitrary
  milliseconds in a theme file is how three systems appeared (F-15).
- The `Duration(milliseconds: 140)` literal in `KitTabs` becomes `Motion.base`.

## 3. Prioritised fix list

Order matters: 1–3 are visible regressions on screens a user sees first; 4–6 are the ones that
make the other fixes hold.

### P0

**P0-1 · Make the colour ladder safe (F-1, F-2, F-3)**
1. `lib/theme/skin.dart`: add `textMuted`, `accentInk`, `borderStrong` as computed getters (or
   constants for the six skins + three layout palettes — table in §2.1). Reuse the existing
   `accentDeepFor` / `onAccentFor` derivation style so `withAccent` / `withBase` keep them legal.
2. `secondary(a)` clamps `a` to the theme muted floor; `accentAt(a)` unchanged.
3. Replace every `color: …accent` on a `Text` or a 17px-or-smaller `Icon` with `accentInk`.
4. `KitRow`'s three hairlines become `borderStrong`; its fill stays `skin.panel`.
5. `KitTabs` unselected border `secondary(0.35)` → `borderStrong`, label `textSecondary` →
   `textMuted`.
*Acceptance:* a grep for `color: .*\.accent\b` returns no `Text` widget; `docs/design/tokens/contrast.py`
reports ≥4.5 for `textMuted`, `accentInk` and `textSecondary@0.8` on all nine themes; the
Minimal `NOW` eyebrow and active tab are legible in a re-render.

**P0-2 · 48dp minimum, once (F-21)**
- `_stepButton`: `34×34` → `48×48`, glyph 18, border `accentAt(0.55)`.
- `KitTabs.height`: `34` → `48`.
- `LayoutSpec.secondaryActionHeight`: `44` → `48`.
- Mini player `_btn`: neighbour width `44` → `48` (keep the 48 height and the glyph sizes).
*Acceptance:* every tappable in the harness is ≥48×48; `flutter test` green; settings at 320dp
shows no row taller than 56 and no control under 48.

**P0-3 · The settings row (F-6, F-7, F-22)**
- `_stepper`: delete `SizedBox(width: 104)`; the value becomes `ConstrainedBox(minWidth: 64)` in
  an `Expanded`-free `Row`, and the label `Expanded` with `maxLines: 2`.
- `KitRow` padding `LTRB(12,7,8,7)` → `LTRB(12,8,12,8)`; row gap `3` → `s1 4`.
- Value formats, one rule — **unit always, space before, no abbreviations**:
  `Fade in → "5 s"` · `Sleep length → "30 min"` · `Weather every → "30 min"`.
*Acceptance:* at 320dp no label ellipsizes before two lines; the three stepper rows read
`5 s` / `30 min` / `30 min`; the value column is ≥64 and never fixed.

**P0-4 · One state language (F-17, F-18, F-19)**
- Toggle: ON = `accent` track + `onAccent` knob; OFF = `borderStrong` track + `textMuted` knob;
  no white outline in either state. Remove `activeThumbColor`/`activeTrackColor` in favour of an
  explicit `Switch` wrapper so both states are ours.
- Selected: `accent` fill + `onAccent` content, one shape per control family, **silhouette never
  changes on selection**. The first-run COLOURS chip gets the same treatment as PERSONA (F-18).
- Tab bar active: `accentInk` label + 2px accent underline; inactive `textMuted`.
- Dependent rows (`WEATHER VARIANTS`, `PLACES`, `WEATHER EVERY`) render `onTap: null` +
  `textMuted` label + `borderSubtle` when their prerequisite is off, and carry a one-line
  `note` naming the switch that enables them.
*Acceptance:* a screenshot of Settings shows ON/OFF distinguishable at a glance on both Abyss
and Minimal; with WEATHER off, WEATHER VARIANTS is visibly unavailable.

**P0-5 · Demote the section band (F-5)**
- Default `chrome.sectionBand` to `"mark"` in the Sonar themes (the form already exists at
  `devices.dart:185`), or keep `"banner"` but reduce it to: height 40, fill `accentAt(0.14)`,
  label `accentInk` at `micro` caps, **no shadow**. Pick one and make it true for every theme.
- Label colour in the mark form: `textPrimary`, tick 3px `accent`, gap `s2 8`.
*Acceptance:* on Settings, the value column is the highest-contrast content; two section headers

## 5. How to verify

1. Captures, before/after in the same matrix:
   ```
   "C:/src/flutter/bin/flutter.bat" test test/design_shots_test.dart --dart-define=PHASE=after
   ```
   The comparator is write-only, so the suite always passes; compare `build/design-shots/before/`
   against `.../after/` by eye, or `compare`/`ffmpeg` the pairs.
2. Gates, in the order the `flutter-ui-features` skill prescribes: the touched widget's own test
   → full `flutter test` → `flutter analyze`. Redirect to a log and read the exit code from the
   log.
3. Numbers, not vibes: `docs/design/tokens/contrast.py` and `derive_tokens.py` are standalone
   Python — re-run them after any palette edit and the tables in §2.1 must still hold.
4. Populated-list check needs a device or an emulator with a music folder; if that is not
   available, say so in the handoff rather than reusing `docs/shots/`.

## 6. Decisions taken (so the implementer does not have to ask)

| question | decision |
|---|---|
| Redesign or systematise? | **Systematise.** Keep the skewed slab, the 12 palettes, the 3 layouts. |
| Which section-header form wins? | The `mark` form (it already exists in the Solid/Glass layouts). Banner survives only as a per-theme opt-in. |
| Muted text: fixed alpha or derived contrast? | **Derived** — a per-theme floor enforced inside `Skin`, not at the call site. |
| Accent as text: allowed? | Only as `accentInk`. Raw `accent` on text is a defect above 18px and a failure below it. |
| Where do the three new colours live? | On `Skin`, next to `accentDeep`/`onAccent`, so `withAccent()` and `withBase()` keep them legal. |
| Do the theme JSONs keep per-theme radii and motion? | Radii yes (the Glass family needs its 24/32). Motion values no — only enum names. |
| Is the skew in scope? | Yes, and it stays: on plates, ticks and the CTA. It is banned on controls whose selected state would change their silhouette. |
